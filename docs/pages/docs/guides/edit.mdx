# Editing

Editing an asset means republishing its metadata: fetch the published document, change what
you want, and write it back onto the same NFT.

## The pattern

```ts twoslash
import { AssetBuilder, Nautilus, NodePersistentRemoteStore } from '@deltadao/nautilus'
import { JsonRpcProvider, Wallet } from 'ethers'

const signer = new Wallet('0x...', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://ocean-node.dev.pontus-x.eu' }
const bootstrap = await Nautilus.create(signer, { config })
const nautilus = await Nautilus.create(signer, {
  config,
  remoteStore: new NodePersistentRemoteStore(bootstrap.getNodeClient())
})
// ---cut---
// 1. Fetch what is published.
const current = await nautilus.getAsset('did:ope:2a6ebce0af...') // [!code focus]

// 2. Change only what you want.
const updated = new AssetBuilder(current) // [!code focus]
  .setName('A better name') // [!code focus]
  .build() // [!code focus]

// 3. Write it back.
const { ddo } = await nautilus.edit(updated) // [!code focus]
```

Editing needs a `remoteStore`, exactly as publishing does — the DDO is signed and stored off
chain either way.

:::info
The merge is **structural**. Setting `name` leaves every other field of the published
document intact, so you never resupply metadata you are not changing. For contrast, the
ocean-cli does a shallow top-level merge, which for a v5 DDO means resupplying the entire
`credentialSubject` to change one field.
:::

The builder must be constructed **from a resolved asset**. That is what supplies the baseline
to merge over; passing a freshly built asset throws.

## What is stripped before signing

`datatokens`, `event` and `stats` are derived by the indexer from chain state, and
`accessDetails`, `views` and `offchain` are decorations some clients attach to a resolved
asset. All of them are removed before the document is signed, so a republish cannot bake in a
stale snapshot. You do not have to remember to delete them.

## Editing metadata

```ts twoslash
import { AssetBuilder, Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const metadataEdit = new AssetBuilder(published)
  .setName('Hourly Weather Observations, 2020–2026')
  .setDescription('Now covering six years')
  .addTags(['revised'])
  .setLicense({ name: 'CC-BY-4.0' }) // [!code focus]
  .build()
```

`created` is preserved and `updated` is bumped for you.

## Editing a service

Load the published service with the [`ServiceBuilder`](/docs/api/ServiceBuilder), change it,
and add it back:

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  Nautilus,
  ServiceBuilder,
  ServiceTypes,
  getServices
} from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const serviceId = getServices(published)[0].id

const revisedService = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  asset: published, // [!code focus]
  serviceId // [!code focus]
})
  .setName('Access Service, revised')
  .setTimeout(7200)
  .build()

const serviceEdit = new AssetBuilder(published).addService(revisedService).build()
```

Services are matched by id, so this replaces the published one rather than adding a second.

### Changing files changes the service id

A service's id is the hash of its encrypted file object. Replace the files — or the endpoint,
since a different node must re-encrypt them — and the rebuilt service necessarily gets a new
id. nautilus removes the old entry so the two do not linger side by side.

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  Nautilus,
  ServiceBuilder,
  ServiceTypes,
  getServices
} from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const newFiles = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  asset: published,
  serviceId: getServices(published)[0].id
})
  .addFile({ // [!code focus]
    type: 'url', // [!code focus]
    url: 'https://data.example/observations-v2.csv', // [!code focus]
    method: 'GET' // [!code focus]
  }) // [!code focus]
  .build()
```

Consumers holding an order against the old service id keep it, but new orders go to the new
one.

## Adding and removing services

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  Nautilus,
  ServiceBuilder,
  ServiceTypes,
  getServices
} from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const extraService = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  serviceType: ServiceTypes.COMPUTE
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setName('Compute')
  .addFile({ type: 'url', url: 'https://data.example/x.csv', method: 'GET' })
  .setPricing({ type: 'free' }) // a new service needs its own datatoken
  .build()

const withExtra = new AssetBuilder(published)
  .addService(extraService) // [!code focus]
  .removeService(getServices(published)[0].id) // [!code focus]
  .build()
```

Only services carrying a **new pricing config** get a new datatoken. That is why
`setPricing` is required on a genuinely new service and blocked on a loaded one.

## Changing a price

Do not do it through the builder — a new pricing config mints a new datatoken and changes the
service id. There is a dedicated call that just sets the rate on the existing exchange:

```ts twoslash
import { Nautilus, getServices } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
await nautilus.setServicePrice(published, getServices(published)[0].id, '2.5') // [!code focus]
```

Only works for fixed-rate services: a free service has a dispenser, which has no rate.

## Editing compute options

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  Nautilus,
  ServiceBuilder,
  ServiceTypes,
  getServiceByType
} from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const computeAsset = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const computeServiceId = getServiceByType(computeAsset, 'compute')?.id as string

const revisedCompute = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  asset: computeAsset,
  serviceId: computeServiceId
})
  .allowAlgorithmNetworkAccess(false)
  .addTrustedAlgorithms([{ did: 'did:ope:926098d069b017dcf...' }]) // [!code focus]
  .removeTrustedAlgorithmPublisher('0x0DB823218e337a...')
  .build()

const computeEdit = new AssetBuilder(computeAsset).addService(revisedCompute).build()
```

Trusted algorithms are re-resolved to their current container and file checksums on every
edit, so an algorithm whose container moved gets its pin updated.

## Changing the lifecycle state

To retire or unlist an asset without touching anything else, one transaction is enough:

```ts twoslash
import { LifecycleStates, Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
await nautilus.setAssetLifecycleState(published, LifecycleStates.ASSET_UNLISTED) // [!code focus]
```

It returns `undefined` without sending anything when the asset is already in that state. If
you are changing metadata anyway, set it on the builder instead with
[`setLifecycleState`](/docs/api/assetbuilder/setLifecycleState).

## Waiting for the change to be visible

The metadata transaction confirms before ocean-node has indexed it, so an immediate re-read
can still return the old document. Wait for your specific transaction:

```ts twoslash
import { AssetBuilder, Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const published = await nautilus.getAsset('did:ope:2a6ebce0af...')
// ---cut---
const { ddo, setMetadataTxReceipt } = await nautilus.edit(
  new AssetBuilder(published).setName('Renamed').build()
)

const indexed = await nautilus.waitForIndexer( // [!code focus]
  ddo.id as string, // [!code focus]
  setMetadataTxReceipt.hash // [!code focus]
) // [!code focus]
```

Passing the transaction hash matters here: without it, `waitForIndexer` is satisfied by the
asset merely existing, which it already did.
