# Publishing

Publishing an asset means creating a data NFT, minting a datatoken for each service, and
writing the asset's metadata onto the NFT.

## What is different in v2

Three changes matter when you come from v1:

1. **The DDO is signed and stored off chain.** Only a `{ remote }` pointer goes on chain, so
   publishing needs a **remote store**. This follows the enterprise-market model and gives
   the asset a real issuer.
2. **DDO v5.** Assets are W3C Verifiable Credentials. `providedBy` is now required, and
   `description` and `license` changed shape — though the builder still takes plain strings.
3. **One transaction instead of three.** The NFT, the first service's datatoken and that
   service's pricing are created together.

::::steps

### Set up an instance with a remote store

The remote store needs an ocean-node client, so the instance is built in two steps.
`NodePersistentRemoteStore` uses the node's own storage, which means no external service:

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { Nautilus, NodePersistentRemoteStore } from '@deltadao/nautilus'

const signer = new Wallet('0x...', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://ocean-node.dev.pontus-x.eu' }

const bootstrap = await Nautilus.create(signer, { config })

const nautilus = await Nautilus.create(signer, {
  config,
  remoteStore: new NodePersistentRemoteStore(bootstrap.getNodeClient()) // [!code focus]
})
```

Prefer IPFS? Swap in `IpfsRemoteStore` with any upload endpoint — see
[`create`](/docs/api/nautilus/create#remotestore).

### Build a service

A service is what consumers actually order. It needs an endpoint, at least one file, and a
pricing scheme.

```ts twoslash
import {
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const service = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setName('Access Service')
  .setTimeout(86400)
  .addFile({ // [!code focus]
    type: 'url', // [!code focus]
    url: 'https://data.example/observations.csv', // [!code focus]
    method: 'GET' // [!code focus]
  }) // [!code focus]
  .setPricing({ type: 'free' })
  .build()
```

Files are encrypted by the node before publishing, so their URLs and any credentials in
them never appear on chain.

:::warning
The file types changed with ocean-node. `graphql` and `smartcontract` are **gone**; `s3`,
`ftp` and `nodePersistentStorage` are **new**. The object types were renamed too —
`UrlFile` is now `UrlFileObject`. See
[`addFile`](/docs/api/servicebuilder/addFile).
:::

`timeout` is how long an order stays valid, in seconds — `0` never expires. Within it,
nautilus reuses an existing order instead of buying another datatoken.

### Build the asset

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const service = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setPricing({ type: 'free' })
  .addFile({ type: 'url', url: 'https://data.example/x.csv', method: 'GET' })
  .build()
// ---cut---
const asset = new AssetBuilder()
  .setType('dataset')
  .setName('Hourly Weather Observations')
  .setDescription('One row per hour, comma separated')
  .setAuthor('deltaDAO')
  .setProvidedBy('deltaDAO AG') // required by DDO v5 // [!code focus]
  .setLicense('https://market.oceanprotocol.com/terms')
  .addTags(['weather', 'timeseries'])
  .setNftTokenName('Weather Data NFT')
  .setNftTokenSymbol('WEATHER-NFT')
  .addService(service)
  .build()
```

`setDescription` takes a plain string and nautilus wraps it into DDO v5's language-tagged
form. Use [`setContentLanguage`](/docs/api/assetbuilder/setContentLanguage) to change the
tag from the `en`/`ltr` default.

### Publish

```ts twoslash
import { Nautilus, type NautilusAsset } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const asset = {} as NautilusAsset
// ---cut---
const { ddo, nftAddress, services } = await nautilus.publish(asset, { // [!code focus]
  waitForIndexer: true // [!code focus]
}) // [!code focus]

console.log('published', ddo.id)
```

`waitForIndexer` blocks until ocean-node has indexed the asset, so the DID is immediately
resolvable. Without it, publish returns as soon as the metadata transaction confirms — which
is earlier than the indexer has seen it.

:::info
Before anything is written, nautilus validates the DDO **locally** against the DDO v5 SHACL
schema. A missing required field fails here, naming the field, having spent no gas. This did
not exist in v1.
:::

## Publishing an algorithm

An algorithm is an asset of type `algorithm` carrying container metadata, served by a
`compute` service:

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'
// ---cut---
const service = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  serviceType: ServiceTypes.COMPUTE
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setPricing({ type: 'free' })
  .addFile({ type: 'url', url: 'https://example.org/algo.js', method: 'GET' })
  .build()

const algorithm = new AssetBuilder()
  .setType('algorithm')
  .setName('Branin Regression')
  .setDescription('Fits a model to the input data')
  .setProvidedBy('deltaDAO AG')
  .setAlgorithm({ // [!code focus]
    language: 'python', // [!code focus]
    version: '0.1.0', // [!code focus]
    container: { // [!code focus]
      entrypoint: 'python $ALGO', // [!code focus]
      image: 'oceanprotocol/algo_dockers', // [!code focus]
      tag: 'python-branin', // [!code focus]
      checksum: 'sha256:8f36c4b2b7b4b0e6b0d0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0' // [!code focus]
    } // [!code focus]
  }) // [!code focus]
  .addService(service)
  .build()
```

## Multiple services on one asset

Useful for offering an open preview alongside a restricted full dataset, or both download
and compute access to the same data. The first service is bundled with the NFT; each further
one gets its own datatoken on the same NFT.

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const endpoint = 'https://ocean-node.dev.pontus-x.eu'
const file = { type: 'url' as const, url: 'https://data.example/x.csv', method: 'GET' }

const download = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint(endpoint)
  .setName('Download')
  .addFile(file)
  .setPricing({ type: 'free' })
  .build()

const compute = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  serviceType: ServiceTypes.COMPUTE
})
  .setServiceEndpoint(endpoint)
  .setName('Compute')
  .addFile(file)
  .setPricing({ type: 'free' })
  .build()
// ---cut---
const asset = new AssetBuilder()
  .setType('dataset')
  .setName('Weather Observations')
  .setProvidedBy('deltaDAO AG')
  .addService(download) // [!code focus]
  .addService(compute) // [!code focus]
  .build()
```
