# Publishing

Publishing an asset means creating a data NFT, minting a datatoken for each service, and
writing the asset's metadata onto the NFT.

## What is different in v2

Three changes matter when you come from v1:

1. **The DDO is signed, encrypted and stored off chain.** Only an encrypted `{ remote }`
   pointer goes on chain, so publishing needs a **remote store**. This follows the
   enterprise-market model and gives the asset a real issuer. Everything is always
   node-encrypted; there is no plaintext mode.
2. **DDO v5.** Assets are W3C Verifiable Credentials. `providedBy` is now required, and
   `description` and `license` changed shape — though the builder still takes plain strings.
3. **One transaction instead of three.** The NFT, the first service's datatoken and that
   service's pricing are created together.

### Set up an instance with a remote store

The remote store holds the encrypted DDO envelope. Use `IpfsRemoteStore` with any IPFS upload
endpoint, here Pinata with the JWT from the environment:

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { IpfsRemoteStore, Nautilus } from '@deltadao/nautilus'

declare const process: { env: Record<string, string | undefined> }

const signer = new Wallet('0x...', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://ocean-node.dev.pontus-x.eu' }

const nautilus = await Nautilus.create(signer, {
  config,
  remoteStore: new IpfsRemoteStore({ // [!code focus]
    uploadUrl: 'https://api.pinata.cloud/pinning/pinFileToIPFS', // [!code focus]
    headers: { Authorization: `Bearer ${process.env.PINATA_JWT}` }, // [!code focus]
    probe: 'upload', // [!code focus]
    gatewayUrl: 'https://gateway.pinata.cloud' // [!code focus]
  }) // [!code focus]
})
```

`probe: 'upload'` makes `publish()` test the store before it sends any transaction, and
`gatewayUrl` is where it reads the stored envelope back before the metadata transaction
(Pinata needs one; a Kubo node is read back without). For a
Kubo node, other pinning services, S3, and why the node's own storage cannot hold DDOs, see
[remote stores](/docs/guides/remote-stores).

### Build a service

A service is what consumers actually order. It needs an endpoint, at least one file, and a
pricing scheme.

```ts twoslash
import {
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const service = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setName('Access Service')
  .setTimeout(86400)
  .addFile({ // [!code focus]
    type: 'url', // [!code focus]
    url: 'https://data.example/observations.csv', // [!code focus]
    method: 'GET' // [!code focus]
  }) // [!code focus]
  .setPricing({ type: 'free' })
  .build()
```

Files are encrypted by the node before publishing, so their URLs and any credentials in
them never appear on chain.

:::warning
The file types changed with ocean-node. `graphql` and `smartcontract` are **gone**; `s3`,
`ftp` and `nodePersistentStorage` are **new**. The object types were renamed too —
`UrlFile` is now `UrlFileObject`. See
[`addFile`](/docs/api/servicebuilder/addFile).
:::

`timeout` is how long an order stays valid, in seconds — `0` never expires. Within it,
nautilus reuses an existing order instead of buying another datatoken.

### Build the asset

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const service = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setPricing({ type: 'free' })
  .addFile({ type: 'url', url: 'https://data.example/x.csv', method: 'GET' })
  .build()
// ---cut---
const asset = new AssetBuilder()
  .setType('dataset')
  .setName('Hourly Weather Observations')
  .setDescription('One row per hour, comma separated')
  .setAuthor('deltaDAO')
  .setProvidedBy('deltaDAO AG') // required by DDO v5 // [!code focus]
  .setLicense('https://market.oceanprotocol.com/terms')
  .addTags(['weather', 'timeseries'])
  .setNftTokenName('Weather Data NFT')
  .setNftTokenSymbol('WEATHER-NFT')
  .addService(service)
  .build()
```

`setDescription` takes a plain string and nautilus wraps it into DDO v5's language-tagged
form. Use [`setContentLanguage`](/docs/api/assetbuilder/setContentLanguage) to change the
tag from the `en`/`ltr` default.

### Publish

```ts twoslash
import { Nautilus, type NautilusAsset } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const asset = {} as NautilusAsset
// ---cut---
const { ddo, nftAddress, services } = await nautilus.publish(asset, { // [!code focus]
  waitForIndexer: true // [!code focus]
}) // [!code focus]

console.log('published', ddo.id)
```

`waitForIndexer` blocks until ocean-node has indexed the asset, so the DID is immediately
resolvable. Without it, publish returns as soon as the metadata transaction confirms — which
is earlier than the indexer has seen it.

If the node records that it **could not** index the asset, the wait throws an
`IndexingError` with the node's message instead of running into its timeout; if the node
simply has not indexed it within the timeout, it throws an `OceanNodeError`. Pass
`{ waitForIndexer: { timeoutMs: 600_000 } }` to wait longer than the 5-minute default. See
[`waitForIndexer`](/docs/api/nautilus/waitForIndexer).

:::info
Before anything is written, nautilus validates the DDO **locally** against the DDO v5 SHACL
schema, and runs the remote store's `check()`. A missing required field or a store that would
refuse the upload fails here, having spent no gas. Local validation did not exist in v1. It
also refuses a DDO too large for the node to decrypt again (see
[`publish`](/docs/api/nautilus/publish#throws)), and a node whose indexer nonce is stuck (see
[`checkIndexerNonce`](/docs/api/nautilus/publish#checkindexernonce)).
Right before the metadata transaction it also runs the store's `verify()`, which reads the
stored envelope back and checks its hash.
:::

## If a publish stops halfway

The DID derives from the NFT address, so the NFT has to be minted before the DDO can be
stored. If anything fails after the mint — the store, the node, the RPC — `publish()` throws a
`PublishIncompleteError` carrying the `nftAddress`. Finish the publish on that NFT instead of
minting a new one:

```ts twoslash
import { Nautilus, PublishIncompleteError, type NautilusAsset } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const asset = {} as NautilusAsset
// ---cut---
try {
  await nautilus.publish(asset)
} catch (error) {
  if (!(error instanceof PublishIncompleteError)) throw error

  // The same asset, or one rebuilt the same way: the datatokens already on the NFT are reused.
  await nautilus.completePublish(error.nftAddress, asset) // [!code focus]
}
```

Before any transaction, `completePublish` checks that the signer owns the NFT and that the
configured factory created it. See [`completePublish`](/docs/api/nautilus/completePublish).

Once the metadata transaction is mined, nothing is left to complete. A wait for the indexer
that fails, or a `MetadataConflictError` (another metadata transaction for the NFT in the
same block), still carries the whole result as `error.published` — see
[`PublishResponse`](/docs/api/PublishResponse#when-the-write-was-mined-but-the-call-throws).

## Publishing an algorithm

An algorithm is an asset of type `algorithm` carrying container metadata, served by a
`compute` service:

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'
// ---cut---
const service = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  serviceType: ServiceTypes.COMPUTE
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .setPricing({ type: 'free' })
  .addFile({ type: 'url', url: 'https://example.org/algo.js', method: 'GET' })
  .build()

const algorithm = new AssetBuilder()
  .setType('algorithm')
  .setName('Branin Regression')
  .setDescription('Fits a model to the input data')
  .setProvidedBy('deltaDAO AG')
  .setAlgorithm({ // [!code focus]
    language: 'python', // [!code focus]
    version: '0.1.0', // [!code focus]
    container: { // [!code focus]
      entrypoint: 'python $ALGO', // [!code focus]
      image: 'oceanprotocol/algo_dockers', // [!code focus]
      tag: 'python-branin', // [!code focus]
      checksum: 'sha256:8f36c4b2b7b4b0e6b0d0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0f0' // [!code focus]
    } // [!code focus]
  }) // [!code focus]
  .addService(service)
  .build()
```

## Multiple services on one asset

Useful for offering an open preview alongside a restricted full dataset, or both download
and compute access to the same data. The first service is bundled with the NFT; each further
one gets its own datatoken on the same NFT.

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const endpoint = 'https://ocean-node.dev.pontus-x.eu'
const file = { type: 'url' as const, url: 'https://data.example/x.csv', method: 'GET' }

const download = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint(endpoint)
  .setName('Download')
  .addFile(file)
  .setPricing({ type: 'free' })
  .build()

const compute = new ServiceBuilder<ServiceTypes.COMPUTE, FileTypes.URL>({
  serviceType: ServiceTypes.COMPUTE
})
  .setServiceEndpoint(endpoint)
  .setName('Compute')
  .addFile(file)
  .setPricing({ type: 'free' })
  .build()
// ---cut---
const asset = new AssetBuilder()
  .setType('dataset')
  .setName('Weather Observations')
  .setProvidedBy('deltaDAO AG')
  .addService(download) // [!code focus]
  .addService(compute) // [!code focus]
  .build()
```

## Try it

Every shape above is a runnable command in [`examples/`](/docs/examples):

```sh
npm start -- store:check                 # test the DDO store first, without a transaction
npm start -- publish:access-dataset      # a downloadable dataset, allowlisted to the publisher and consumer
npm start -- publish:compute-dataset     # a dataset algorithms can run against
npm start -- publish:saas                # a SaaS offer
npm start -- publish:multi-service       # one NFT carrying two services
npm start -- publish:validate            # build and validate, without publishing
npm start -- publish:resume publish:access-dataset 0xNFT… 0xDatatoken…   # finish a stopped publish
```
