# UserCustomParameters

Interface thats used when handling publisher specific userdata.

## Usage

:::code-group

```ts twoslash [access]
import { Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('1234'))
// ---cut---
await nautilus.access({
    assetDid: 'did:ope:1234...',
    userdata:{ // [!code focus]
        text: 'value', // [!code focus]
        number: 123, // [!code focus]
        option: 'selected', // [!code focus]
        boolean: true // [!code focus]
    } // [!code focus]
})
```

```ts twoslash [compute]
import { Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('1234'))
// ---cut---
await nautilus.compute({
    dataset: {
        did: 'did:ope:1234...',
        userdata:{ // [!code focus]
            text: 'value' // [!code focus]
        } // [!code focus]
    },
    algorithm: {
        did: 'did:ope:abcd...',
        userdata: { // [!code focus]
            number: 123 // [!code focus]
        }, // [!code focus]
        algocustomdata: { // [!code focus]
            boolean: true, // [!code focus]
            select: 'option' // [!code focus]
        } // [!code focus]
    }
    
})
```
  :::

## Properties

The interface is defined as follows:

```ts twoslash
interface UserCustomParameters {
    [key: string]: any
}
```

This means any data that is needed for the requested asset to work is supported.
The keys will be defined by the publisher of the respective asset and can be found in the metadata.

If you want to learn more about how you can specify these custom parameters for your assets, you can find more information on the [`ConsumerParameterBuilder` documentation](/docs/api/ConsumerParameterBuilder).

However, there are a few most common scenarios (e.g. supported by marketplace and portal frontends).

### Text Parameter
- Type: `string`

```ts twoslash [compute]
import type { UserCustomParameters } from '@oceanprotocol/lib'
// ---cut---
const userdata = {
    textParameter: 'value' // [!code focus]
} satisfies UserCustomParameters
```


### Number Parameter
- Type: `number`

```ts twoslash [compute]
import type { UserCustomParameters } from '@oceanprotocol/lib'
// ---cut---
const userdata = {
    numberParameter: 1234 // [!code focus]
} satisfies UserCustomParameters
```

### Boolean Parameter
- Type: `boolean`

```ts twoslash [compute]
import type { UserCustomParameters } from '@oceanprotocol/lib'
// ---cut---
const userdata = {
    booleanParameter: false // [!code focus]
} satisfies UserCustomParameters
```

### Select Parameter
- Type: `string`

```ts twoslash [compute]
import type { UserCustomParameters } from '@oceanprotocol/lib'
// ---cut---
const userdata = {
    selectParameter: 'option' // [!code focus]
} satisfies UserCustomParameters
```
In the select case, you have to pass over one of the options defined in the metadata of the requested asset.

## Validation

`access()`, `compute()` and `freeCompute()` check the values against what the asset
declares before anything is sent: a download's `userdata` and a compute input's `userdata`
against the service's `consumerParameters`, and an algorithm's `algocustomdata` against the
`consumerParameters` of its algorithm metadata.

- The values must be a plain object (an object literal): not an array, a string, a `Date`,
  a `Map`, a `Set` or a class instance.
- A `required` parameter must have a value. `undefined` and `null` count as absent. An
  absent optional parameter stays absent; nautilus does not fill in its `default`.
- `text` takes a string, `number` a finite number (not a numeric string such as `'5'`),
  `boolean` `true` or `false`, and `select` a string that is one of its option keys.
- A `select` whose options are missing, empty or malformed is a broken declaration: any
  value for it is refused, since there is nothing to check it against. Leave it absent if
  it is optional, or ask the publisher to fix the asset.
- Keys the asset does not declare are refused, so a misspelt key does not travel to the
  data source unnoticed: a download's `userdata` is appended to the file's URL as query
  parameters. An asset that declares no parameters takes the values as they are.

What is sent is a copy of the values without the keys set to `undefined` or `null`, whether
or not the asset declares parameters: `{ surname: 'Doe', age: null }` reaches the node, the
download URL or the job as `{ surname: 'Doe' }`, never as `age=null`.

A mismatch throws a `ConsumerParameterError` before the node is asked for a fee and before
any transaction. `error.issues` lists every refused value, and `error.did`,
`error.serviceId` and `error.field` (`'userdata'` or `'algocustomdata'`) say where it was
going. Each issue is `{ parameter, reason, message }`, `reason` one of:

| `reason` | Meaning |
| --- | --- |
| `'missing'` | A `required` parameter is absent (`undefined` or `null`). |
| `'wrong-type'` | The value does not have the declared type. |
| `'not-an-option'` | A `select` value is not one of its option keys. |
| `'invalid-declaration'` | A `select` declares no usable options, so no value fits. |
| `'unknown'` | The key is not a declared parameter. |
| `'not-object'` | The values are not a plain object. |

To validate a form before calling, use `checkConsumerParameters`, which returns the same
issues instead of throwing:

```ts twoslash
import {
  checkConsumerParameters,
  getServiceByType,
  Nautilus
} from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const asset = await nautilus.getAsset('did:ope:1234...')
const service = getServiceByType(asset, 'access')

const issues = checkConsumerParameters(service?.consumerParameters, { rows: '5' }) // [!code focus]
// [{ parameter: 'rows', reason: 'wrong-type', message: "'rows' must be a finite number, …" }]
```
