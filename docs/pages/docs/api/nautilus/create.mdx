# create

Creates a new nautilus instance.

## Usage

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { Nautilus } from '@deltadao/nautilus'

const provider = new JsonRpcProvider('https://rpc.dev.pontus-x.eu')
const signer = new Wallet('0x...', provider)

const nautilus = await Nautilus.create(signer, { // [!code focus]
  config: { oceanNodeUri: 'https://node.example.org' } // [!code focus]
}) // [!code focus]
```

The chain is read from the signer's provider, so there is no chain parameter. nautilus then
merges `ConfigHelper`'s defaults for that chain with whatever you pass in `config`. A
`config.chainId` that differs from the provider's chain throws, because the contract
addresses would then belong to another chain than the transactions.

`oceanNodeUri` must be `https://`, except on `localhost`, `127.0.0.0/8`, `::1` and
`*.localhost`: the plaintext DDO pointer and the signed DDO go to the node for encryption.
See [`allowInsecureTransport`](#allowinsecuretransport).

:::warning
ocean.js's `ConfigHelper` ships contract addresses for a set of chains, including
**Pontus-X devnet (32456)** and **OP Sepolia (11155420)**. On a chain it does not know, pass
the contract addresses yourself — `nftFactoryAddress`, `fixedRateExchangeAddress` and
`dispenserAddress` are all validated at construction, so a missing one fails immediately
rather than mid-publish.
:::

## Returns

- Type: `Promise<Nautilus>`

## Parameters

### signer

- Type: `Signer` (ethers **v6**)

nautilus v2 requires ethers v6. A v5 `Signer` is not structurally compatible.

### options (optional)

- Type: `NautilusOptions`

#### Properties

##### config

- Type: `Partial<Config>`

Overrides merged over `ConfigHelper`'s defaults. `chainId`, if you pass it, must be the
chain the signer's provider is on.

One `oceanNodeUri` now replaces v1's `metadataCacheUri` and `providerUri` — a single
ocean-node serves metadata, provider services and the indexer. There is no `subgraphUri`:
pricing comes from chain reads.

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { Nautilus } from '@deltadao/nautilus'
const signer = new Wallet('0x1234', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
// ---cut---
const nautilus = await Nautilus.create(signer, {
  config: { // [!code focus]
    oceanNodeUri: 'https://node.example.org', // [!code focus]
    nftFactoryAddress: '0x...', // [!code focus]
    fixedRateExchangeAddress: '0x...', // [!code focus]
    dispenserAddress: '0x...' // [!code focus]
  } // [!code focus]
})
```

##### remoteStore

- Type: `RemoteStore`

Where the encrypted DDO envelope is stored. **Required to publish or edit**, because nautilus
writes an encrypted `{ remote }` pointer on chain rather than the document itself.

Use `IpfsRemoteStore`, which posts to any IPFS upload endpoint — a Kubo node, or a pinning
service such as Pinata:

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { IpfsRemoteStore, Nautilus } from '@deltadao/nautilus'
const signer = new Wallet('0x1234', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://node.example.org' }
// ---cut---
const nautilus = await Nautilus.create(signer, {
  config,
  remoteStore: new IpfsRemoteStore({ // [!code focus]
    uploadUrl: 'http://127.0.0.1:5001/api/v0/add', // [!code focus]
    probe: 'upload' // [!code focus]
  }) // [!code focus]
})
```

ocean-node resolves the pointer through the same storage layer it uses for asset files, so a
custom `RemoteStore` can also return a `url`, `s3`, `arweave` or `ftp` pointer, and nautilus
ships an `S3RemoteStore` too. `NodePersistentRemoteStore` is **rejected**: ocean-node 4.2
cannot read a DDO from its own bucket storage. See
[remote stores](/docs/guides/remote-stores#storage-options).

##### ddoSigner

- Type: `DdoSigner`

Signs the DDO as a verifiable credential. Defaults to `Eip191VcSigner`, which signs with
the Ethereum key and sets the issuer to the signer's address.

Pass a `WaltIdVcSigner` to issue from a real DID instead — see the
[identity guide](/docs/guides/identity).

##### credentials

- Type: `CredentialProvider`

Satisfies credential-gated access. Omit it and nautilus skips SSI entirely.

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { Nautilus, WaltIdCredentialProvider } from '@deltadao/nautilus'
const signer = new Wallet('0x1234', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://node.example.org' }
const bootstrap = await Nautilus.create(signer, { config })
// ---cut---
const nautilus = await Nautilus.create(signer, {
  config,
  credentials: new WaltIdCredentialProvider(bootstrap.getNodeClient(), { // [!code focus]
    walletApi: 'https://wallet.example.org' // [!code focus]
  }) // [!code focus]
})
```

##### allowInsecureTransport

- Type: `boolean`
- Default: `false`

Accept a plain `http://` `oceanNodeUri` on a host other than `localhost`, `127.0.0.0/8`, `::1`
or `*.localhost`, for example on a private network. Without it, `create` throws for such a
URI. The URI is judged as `fetch` parses it, so `http:host` counts as plain `http://`; see
[the ocean-node URI](/docs/guides/config#the-ocean-node-uri). A peer id or multiaddr is not affected. The node
client applies the same setting to the service endpoints it encrypts and checks files on.

`S3RemoteStore` and `IpfsRemoteStore` have their own `allowInsecureTransport` option for their
endpoints.

##### requestTimeoutMs

- Type: `number`
- Default: `120000` (120 s)

How long one `encrypt` call to the node may take, including the signature and one retry after
a rejected nonce. Passed to the node clients `create` builds; see
[`OceanNodeClient`](/docs/api/node/OceanNodeClient).

##### maxProviderFee

- Type: `TokenAmount | TokenAmount[]`, where `TokenAmount` is
  `{ token: string; amount: bigint | string }`

The default ceiling on the provider fees of every [`access`](/docs/api/nautilus/access) and
[`compute`](/docs/api/nautilus/compute) call, per token, in the token's smallest unit. A
call's own `maxProviderFee` replaces it.

:::warning[Set a fee ceiling]
The node chooses the provider fee: its token, its amount and who receives it. For a
download, that node is the service's `serviceEndpoint`, which the publisher chooses.
Without a ceiling or a confirmation callback, nautilus pays only zero fees and throws a
`ProviderFeeNotAllowedError` for any other, before anything is spent. Set the most you are
prepared to pay per call, in the tokens you expect fees in:

```ts twoslash
import { JsonRpcProvider, parseUnits, Wallet } from 'ethers'
import { Nautilus } from '@deltadao/nautilus'
const signer = new Wallet('0x1234', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://node.example.org' }
const feeToken = '0x...'
const paymentToken = '0x...'
// ---cut---
const nautilus = await Nautilus.create(signer, {
  config,
  maxProviderFee: { token: feeToken, amount: parseUnits('0.5', 18) }, // [!code focus]
  maxEscrowPayment: { token: paymentToken, amount: parseUnits('5', 18) } // [!code focus]
})
```
:::

##### confirmProviderFees

- Type: `(fees: ProviderFeeQuote[]) => boolean | Promise<boolean>`

The default confirmation for provider fees `maxProviderFee` does not cover, for example to
ask a user. See [`access`](/docs/api/nautilus/access#confirmproviderfees-optional).

##### maxEscrowPayment

- Type: `TokenAmount | TokenAmount[]`

The default ceiling on what one [`compute`](/docs/api/nautilus/compute) job may lock in
escrow, per payment token, in the token's smallest unit.

nautilus funds only the chain config's `escrow` contract, whatever contract the node names.
ocean.js's `ConfigHelper` ships it for some chains (OP Sepolia among them); on the others,
pass it as `config.escrow`, or paid compute is refused.

##### confirmEscrowPayment

- Type: `(payment: EscrowPaymentQuote) => boolean | Promise<boolean>`

The default confirmation for an escrow payment `maxEscrowPayment` does not cover. See
[`compute`](/docs/api/nautilus/compute#confirmescrowpayment-optional).

## Throws

- When `config.chainId` differs from the chain of the signer's provider, or the signer has no
  provider.
- When `oceanNodeUri` is missing, or is plain `http://` on a non-loopback host without
  `allowInsecureTransport`.
- When `nftFactoryAddress`, `fixedRateExchangeAddress` or `dispenserAddress` is missing or not
  an address.
- When `maxProviderFee` or `maxEscrowPayment` has an entry whose `token` is not an address,
  whose `amount` is not a non-negative integer, or whose token is listed twice, or when
  `confirmProviderFees` or `confirmEscrowPayment` is not a function.
