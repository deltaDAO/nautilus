# freeCompute

Start a free Compute-to-Data job: no order, no escrow, no payment token.

## Usage

```ts twoslash
import { Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const environments = await nautilus.getComputeEnvironments()
const free = environments.find((environment) => environment.free)

const { jobs } = await nautilus.freeCompute({ // [!code focus]
  dataset: { did: 'did:ope:1234abcd...' }, // [!code focus]
  algorithm: { did: 'did:ope:5678wxyz...' }, // [!code focus]
  computeEnv: free?.id // [!code focus]
}) // [!code focus]
```

New in v2. The environment must expose a `free` configuration, and its access list may
still restrict who can use it — an environment without one throws, naming it.

Policy-server sessions are still opened for every input, as for
[`compute`](/docs/api/nautilus/compute): free of charge is not the same as ungated.

## Returns

- Type: `{ jobs: ComputeJob[]; environment: ComputeEnvironment }`

No `orders` or `initializeResults`, because nothing was ordered or quoted.

## Parameters

### config

- Type: `FreeComputeConfig`

The same as [`ComputeConfig`](/docs/api/nautilus/compute) minus `paymentToken` and
`maxJobDuration`. Resources default from the environment's `free.resources`: each one's
minimum, raised to `1` for `cpu`, `ram` and `disk` within its maximum (see
[`resources`](/docs/api/nautilus/compute#resources-optional)).

Each job's `jobId` is `<environmentHash>-<jobId>`, the id every job method takes.

Consumer parameters are checked as in [`compute`](/docs/api/nautilus/compute): an input's
`userdata` or the algorithm's `algocustomdata` that does not fit what the asset declares
throws a `ConsumerParameterError` before the job is sent.
