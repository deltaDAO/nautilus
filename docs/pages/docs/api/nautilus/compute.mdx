# compute

Start a paid Compute-to-Data job.

## Usage

```ts twoslash
import { Nautilus } from '@deltadao/nautilus'
import { parseUnits, Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
const paymentToken = '0x...'
// ---cut---
const { jobs } = await nautilus.compute({ // [!code focus]
  dataset: { did: 'did:ope:1234abcd...' }, // [!code focus]
  algorithm: { did: 'did:ope:5678wxyz...' }, // [!code focus]
  // the most the job may lock in escrow, and pay in provider fees // [!code focus]
  maxEscrowPayment: { token: paymentToken, amount: parseUnits('5', 18) }, // [!code focus]
  maxProviderFee: { token: paymentToken, amount: parseUnits('0.5', 18) } // [!code focus]
}) // [!code focus]

const jobId = jobs[0].jobId
```

:::warning[Set a ceiling for fees and escrow]
The compute node chooses the provider fee of every input (token, amount and recipient) and
the amount the job locks in escrow. nautilus pays a non-zero provider fee only within
[`maxProviderFee`](#maxproviderfee-optional) or with
[`confirmProviderFees`](#confirmproviderfees-optional), and funds escrow only within
[`maxEscrowPayment`](#maxescrowpayment-optional) or with
[`confirmEscrowPayment`](#confirmescrowpayment-optional). It funds only the chain config's
`escrow` contract, whatever contract the node names. Each refusal is thrown before any
approval, deposit or order. Set the ceilings once with
[`Nautilus.create`](/docs/api/nautilus/create#maxproviderfee), or per call here.
:::

:::warning
C2D v2 changed the compute model substantially. Resources are now requested explicitly,
payment runs through an escrow contract, and all datasets travel in one array. See the
[migration guide](/docs/migration#9-compute).
:::

What happens in order:

1. Every input is resolved and its compute service selected.
2. Credentials are satisfied for **all** inputs. A failure here aborts the whole job with
   nothing spent — the reason this comes first.
3. `initializeCompute` quotes the job: provider fees, reusable orders and the escrow amount.
   The provider fee of every input that will be ordered is checked locally, as for
   [`access`](/docs/api/nautilus/access): a fee that is missing, lacks a field, or that the
   datatoken would reject throws a `ProviderFeeSignatureError` before escrow or any order.
   A compute fee is the same on every request, so `initializeCompute` is called once and a
   bad fee is refused at once, not requested again; contact the node operator if this
   happens.
4. Everything the quote would spend is checked against what you allowed, before the first
   transaction:
   - the inputs' non-zero provider fees, summed per token, against `maxProviderFee`, or
     `confirmProviderFees` asked once with all of them (`ProviderFeeNotAllowedError`);
   - the escrow quote: its contract must be the chain config's `escrow`, and its chain,
     token and payee the job's own (`EscrowPaymentNotAllowedError`, which no callback
     overrides); its amount must be within `maxEscrowPayment`, or `confirmEscrowPayment`
     must return `true` (`EscrowPaymentNotAllowedError` again);
   - the wallet must hold what has to be deposited.
5. Escrow is funded in exact amounts: nautilus approves the escrow contract for the
   shortfall only (what the job needs less what is already available in escrow), deposits
   it, and authorises the environment's account to lock the job's amount on top of its
   current locks. A standing allowance or authorisation that already covers the job is left
   as it is. Nothing is approved for more than is deposited.
6. Each input is ordered — reusing an existing order where the node says one is valid —
   allowed to pay exactly the provider fee approved in step 4.
7. The job starts.

### Choosing an environment

v1 silently used the node's first environment. Prefer choosing deliberately, since
resources, duration limits and fees differ:

```ts twoslash
import { Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const environments = await nautilus.getComputeEnvironments()
const environment = environments[0]

const { jobs } = await nautilus.compute({
  dataset: { did: 'did:ope:1234abcd...' },
  algorithm: { did: 'did:ope:5678wxyz...' },
  computeEnv: environment.id, // [!code focus]
  resources: [ // [!code focus]
    { id: 'cpu', amount: 2 }, // [!code focus]
    { id: 'ram', amount: 2 } // [!code focus]
  ] // [!code focus]
})
```

## Returns

- Type: `ComputeResult`

#### Properties

##### jobs

- Type: `ComputeJob[]`

The started jobs. Poll them with [`getComputeStatus`](/docs/api/nautilus/getComputeStatus).

##### environment

- Type: `ComputeEnvironment`

The environment the job actually runs in, including the one nautilus picked for you.

##### initializeResults

- Type: `ProviderComputeInitializeResults`

What the node quoted: per-input provider fees and reusable orders, plus the escrow payment.

##### orders

- Type: `Record<string, string>`

The order transaction backing each input, keyed by `did#serviceId` so two inputs on the same asset keep separate orders.

## Parameters

### config

- Type: `ComputeConfig`

#### Properties

##### dataset

- Type: `ComputeAssetRef`

`{ did, serviceId?, userdata? }`. Defaults to the asset's first `compute` service.

:::info
This type was renamed from `ComputeAsset` in v1, because ocean.js exports a different type
under that name. Having both in scope was a standing source of confusion.
:::

##### algorithm

- Type: `ComputeAlgorithmRef`

`ComputeAssetRef` plus `algocustomdata?` and `envs?` (environment variables for the
container).

##### additionalDatasets (optional)

- Type: `ComputeAssetRef[]`

Extra inputs. C2D v2 passes every dataset in one array; nautilus assembles that for you.

##### computeEnv (optional)

- Type: `string`

Environment id. Defaults to the node's first, which is logged when it happens.

##### resources (optional)

- Type: `ComputeResourceRequest[]`

`[{ id: 'cpu', amount: 2 }]`. Ids come from `ComputeEnvironment.resources`. Defaults to
each resource's declared minimum.

##### paymentToken (optional)

- Type: `string`

Must be a token the environment prices for this chain — `fees` is keyed by chain id.
Defaults to the first accepted token; an unaccepted one fails with the list of accepted ones.

##### maxJobDuration (optional)

- Type: `number`

Seconds. Capped to the environment's `maxJobDuration`, with a warning when it is.

##### output (optional)

- Type: `ComputeOutput`

`{ remoteStorage?, encryption? }`. v1's hardcoded `publishAlgorithmLog` and `publishOutput`
flags no longer exist.

##### outputBucketId (optional)

- Type: `string`

Store results in an ocean-node bucket instead. Mutually exclusive with `output`.

##### additionalViewers (optional)

- Type: `string[]`

Extra addresses allowed to read the results.

##### metadata (optional)

- Type: `Record<string, string | number | boolean>`

##### queueMaxWaitTime (optional)

- Type: `number`

Seconds to wait in the queue when resources are unavailable.

##### skipCredentials (optional)

- Type: `boolean`

##### maxProviderFee (optional)

- Type: `TokenAmount | TokenAmount[]`, where `TokenAmount` is
  `{ token: string; amount: bigint | string }`
- Default: the [`Nautilus.create`](/docs/api/nautilus/create#maxproviderfee) option, else none

The most the job may pay in provider fees, per token, in the token's smallest unit: the sum
of every input's fee in that token. See [`access`](/docs/api/nautilus/access#maxproviderfee-optional).

##### confirmProviderFees (optional)

- Type: `(fees: ProviderFeeQuote[]) => boolean | Promise<boolean>`

Asked once, with every input's non-zero fee, when `maxProviderFee` does not cover them.
Return `true` to pay them all.

##### maxEscrowPayment (optional)

- Type: `TokenAmount | TokenAmount[]`
- Default: the [`Nautilus.create`](/docs/api/nautilus/create#maxescrowpayment) option, else none

The most the job may lock in escrow, per payment token, in the token's smallest unit (the
node quotes `payment.amount` in those units). Without it or `confirmEscrowPayment`, a paid
job is refused with an `EscrowPaymentNotAllowedError` before anything is spent; a quote of
zero needs neither.

##### confirmEscrowPayment (optional)

- Type: `(payment: EscrowPaymentQuote) => boolean | Promise<boolean>`

Asked when `maxEscrowPayment` does not cover the quote, with
`{ escrowAddress, token, amount, payee, minLockSeconds, chainId }` (`amount` a `bigint`).
Return `true` to fund it. It is asked only after the escrow contract, chain, token and payee
passed their checks.

## Throws

- `ProviderFeeSignatureError` and `ProviderFeeNotAllowedError`, as for
  [`access`](/docs/api/nautilus/access#throws).
- `EscrowPaymentNotAllowedError`, with `error.reason`:
  - `'unknown-escrow'`: the chain config has no `escrow` address. ocean.js ships it for some
    chains; pass `config: { escrow: '0x…' }` to `Nautilus.create` for the others;
  - `'escrow-address'`: the node named another escrow contract;
  - `'mismatch'`: the quote is for another chain, token or payee, or its amount is not an
    exact integer;
  - `'no-limit'`, `'over-limit'` or `'declined'`: the amount was not allowed.
- An `Error` when the wallet cannot cover the deposit.

All of these are thrown before any approval, deposit or order.
