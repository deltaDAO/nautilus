# query

Search the node's metadata index directly.

New in v2.

## Usage

```ts twoslash
import { Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const results = await nautilus.query({ // [!code focus]
  query: { // [!code focus]
    bool: { // [!code focus]
      filter: [{ term: { 'credentialSubject.metadata.type': 'dataset' } }] // [!code focus]
    } // [!code focus]
  }, // [!code focus]
  size: 25 // [!code focus]
}) // [!code focus]
```

An escape hatch for searches nautilus does not wrap. The query is passed to the node
untouched.

:::warning
Field paths follow the **DDO v5** index mapping, so metadata lives under
`credentialSubject.metadata.*` rather than at the top level. Note also that several fields
are indexed with `enabled: false` and are therefore not queryable at all —
`credentials`, `license`, `links`, `attachments`, `algorithm` and `additionalInformation`
among them.
:::

## Returns

- Type: `unknown`

The node's raw response. It is not typed, because the shape depends on the node's version
and database backend. ocean-node 4.x answers with an array of pages,
`[{ results: [ddo, …], totalResults }]`, the DDOs themselves in `results`; an
Elasticsearch-style answer is `{ hits: { hits: [{ _source }] } }`.

For the common case of resolving several known DIDs, use
[`getAssets`](/docs/api/nautilus/getAssets) instead, which unwraps either shape for you and
refuses a DDO whose `id` is not a DID asked for. `query()` checks no hit against any DID.

## Parameters

### query

- Type: `SearchQuery`

`{ query, from?, size?, sort?, aggs? }`.
