# access

Download an asset: order the service if needed, then get a one-time URL.

## Usage

```ts twoslash
import { Nautilus } from '@deltadao/nautilus'
import { parseUnits, Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const { url } = await nautilus.access({ // [!code focus]
  assetDid: 'did:ope:1234abcd...', // [!code focus]
  // the most this download may pay the node, in the fee token's smallest unit // [!code focus]
  maxProviderFee: { token: '0x...', amount: parseUnits('0.5', 18) } // [!code focus]
}) // [!code focus]

// fetch the actual data
const data = await fetch(url)
```

:::warning[Set a fee ceiling]
The provider fee's token, amount and recipient are chosen by the node the service names in
its `serviceEndpoint`, and the publisher chooses that node. The fee signature only proves
that this node signed the fee, not that the fee is reasonable. So nautilus pays a non-zero
provider fee only within [`maxProviderFee`](#maxproviderfee-optional) or when
[`confirmProviderFees`](#confirmproviderfees-optional) returns `true`, and otherwise throws a
`ProviderFeeNotAllowedError` before anything is spent. A fee of zero always passes. Set the
ceiling once for every call with [`Nautilus.create`](/docs/api/nautilus/create#maxproviderfee),
or per call here.
:::

What happens in order:

1. If the service is credential-gated, the configured
   [credential provider](/docs/guides/identity) satisfies the policy. This happens
   **before** any spend, so a failed presentation costs nothing.
2. The node is asked for provider fees and whether a previous order can be reused. Before
   ordering, nautilus checks that the provider fee signature recovers to
   `providerFeeAddress` the way the datatoken contract verifies it, since an order with any
   other fee reverts. If it does not, nautilus calls `initialize` again, 1.1 s later: at
   most 3 calls in total (2 retries). It stops early when the node signs the same fee
   again, and does not ask again at all for a service with `timeout: 0`, whose fee is the
   same on every request. A fee that is missing or lacks a field is refused at once. In
   every case it throws a `ProviderFeeSignatureError` before any approval, purchase or
   order.
3. A non-zero fee must be allowed by `maxProviderFee` or `confirmProviderFees`, or nautilus
   throws a `ProviderFeeNotAllowedError`, again before any chain read, approval, purchase or
   order. The order is then allowed to pay exactly the fee that was allowed.
4. An existing order is reused where possible — extended if a new fee period is due, or
   used as-is if not. Otherwise a datatoken is bought and a new order placed. Everything the
   order pulls from you (the purchase, the publish-market fee and the provider fee) is
   approved with one allowance per token and spender, after every check has passed.
5. The download URL is built, carrying the verifier session if there was one.

## Returns

- Type: `AccessResult`

:::warning
In v1 this returned a bare URL string. It now returns an object, so that the order backing
the download is visible to the caller.
:::

#### Properties

##### url

- Type: `string`

The one-time URL to download the raw data.

##### did / serviceId

- Type: `string`

The asset and the service that were actually accessed — useful when you let nautilus pick
the service.

##### transferTxId

- Type: `string`

The order authorising this download.

##### reusedOrder

- Type: `boolean`

`true` when an existing order was reused rather than a new one paid for.

## Parameters

### config

- Type: `AccessConfig`

#### Properties

##### assetDid

- Type: `string`

The identifier of the asset to access.

##### serviceId (optional)

- Type: `string`

Which service to download from. Defaults to the asset's first `access` service.

##### fileIndex (optional)

- Type: `number`

Which file of the service to download. Defaults to `0`.

##### userdata (optional)

- Type: [`UserCustomParameters`](/docs/api/UserCustomParameters)

Values for the service's consumer parameters. See the
[ConsumerParameterBuilder](/docs/api/ConsumerParameterBuilder).

##### skipCredentials (optional)

- Type: `boolean`

Skip the credential presentation even for a gated service. Only useful when you already
hold a valid verifier session and supplied it as a `StaticCredentialProvider`.

##### maxProviderFee (optional)

- Type: `TokenAmount | TokenAmount[]`, where `TokenAmount` is
  `{ token: string; amount: bigint | string }`
- Default: the [`Nautilus.create`](/docs/api/nautilus/create#maxproviderfee) option, else none

The most this call may pay in provider fees, per token, in the token's smallest unit (wei
for an 18-decimal token; `parseUnits('0.5', 18)` from ethers converts). A fee in a token not
listed is not covered. `amount` is a `bigint` or a decimal integer string; anything else
throws before the node is asked for a fee.

##### confirmProviderFees (optional)

- Type: `(fees: ProviderFeeQuote[]) => boolean | Promise<boolean>`
- Default: the [`Nautilus.create`](/docs/api/nautilus/create#confirmproviderfees) option, else none

Asked when `maxProviderFee` does not cover the fee, for example to show it to a user. It
receives each non-zero fee as `{ token, amount, collector, datatoken, did, serviceId }`
(`amount` a `bigint` in the token's smallest unit, `collector` the `providerFeeAddress` that
receives it). Return `true` to pay, `false` to refuse. It is not called for a zero fee or a
fee within the ceiling, and an error it throws propagates before anything is spent.

## Throws

- `ProviderFeeSignatureError`: the node's fee is missing, incomplete, or its signature would
  fail the datatoken's check.
- `ProviderFeeNotAllowedError`: the fee is not zero and neither `maxProviderFee` nor
  `confirmProviderFees` allows it. `error.fees` lists the fees, `error.reason` is
  `'no-limit'`, `'over-limit'` or `'declined'`.

Both are thrown before any approval, purchase or order.
