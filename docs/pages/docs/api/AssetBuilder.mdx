# AssetBuilder

Builds the metadata for an asset you want to publish or edit, with a typesafe fluent API.

## Instantiating

Two modes, chosen by whether you pass an existing asset.

:::code-group
```ts twoslash [create]
import { AssetBuilder } from '@deltadao/nautilus'

const builder = new AssetBuilder() // [!code focus]
// @log: an empty asset, to be filled in
```

```ts twoslash [edit]
import { AssetBuilder, Nautilus } from '@deltadao/nautilus'
import { Wallet } from 'ethers'

const nautilus = await Nautilus.create(new Wallet('0x1234'))

const published = await nautilus.getAsset( // [!code focus]
  'did:ope:2a6ebce0af9361e2c7d1e1e7909ecac3e4cabb4f089f7edd51865e0b77a5c216' // [!code focus]
) // [!code focus]

const editBuilder = new AssetBuilder(published) // [!code focus]
```
:::

:::info
v1 called the argument `aquariusAsset`. Aquarius no longer exists as a separate service —
ocean-node serves the metadata API — so it is simply the asset from
[`getAsset`](/docs/api/nautilus/getAsset).
:::

In edit mode the builder seeds itself from the published document, including its owner and
lifecycle state, and immediately strips the indexer-derived fields so they can never be
signed back in. Setting one field leaves everything else intact: the merge is structural,
not top-level, so you never have to resupply metadata you are not changing.

`reset()` returns to whichever state the constructor produced. In edit mode that means the
loaded asset — v1 emptied the builder, which made `reset()` unusable while editing.

## A minimal new asset

```ts twoslash
import {
  AssetBuilder,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const minimalService = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
  .setServiceEndpoint('https://ocean-node.dev.pontus-x.eu')
  .addFile({ type: 'url', url: 'https://data.example/x.csv', method: 'GET' })
  .setPricing({ type: 'free' })
  .build()
// ---cut---
const minimal = new AssetBuilder()
  .setType('dataset') // required
  .setName('Hourly Weather Observations') // required
  .setProvidedBy('deltaDAO AG') // required by DDO v5 // [!code focus]
  .addService(minimalService) // at least one
  .build()
```

`build()` rejects a new asset missing `name`, `type` or `providedBy`, and one with no
services. An `algorithm` also needs container metadata. Everything else is checked by
[`publish`](/docs/api/nautilus/publish), which validates the whole DDO locally against the
DDO v5 schema before spending gas.

:::warning
`setProvidedBy` is **new and required**. DDO v4 had no equivalent field.
:::

## DDO v5 changes worth knowing

Three setters take the same arguments as in v1 but produce a different shape, because DDO v5
changed the fields. The builder absorbs that, so you keep passing plain strings.

```ts twoslash
import { AssetBuilder } from '@deltadao/nautilus'
const shapes = new AssetBuilder()
// ---cut---
// Stored as { '@value', '@language', '@direction' } — v4 used a plain string.
shapes.setDescription('One row per hour, comma separated')

// Stored as { name } — v4 used a plain string. Pass the object form for ODRL terms.
shapes.setLicense('https://market.oceanprotocol.com/terms')

// Stored as a { label: url } map — v4 used an array. An array still works, keyed by index.
shapes.addLinks(['https://docs.example'])
shapes.addLinks({ docs: 'https://docs.example' })
```

`setContentLanguage` was **repurposed**. In v4 it wrote a `contentLanguage` metadata field;
v5 moved the language onto each value, so it now sets the tag applied to every
language-tagged field the builder emits:

```ts twoslash
import { AssetBuilder } from '@deltadao/nautilus'
const language = new AssetBuilder()
// ---cut---
language.setContentLanguage('de', 'ltr') // [!code focus]
language.setDescription('Stündliche Wetterbeobachtungen')
// @log: description: { '@value': '...', '@language': 'de', '@direction': 'ltr' }
```

It defaults to `en` / `ltr`.

## Gating access

Address lists work as they did in v1. Verifiable-credential gating is new in DDO v5.

```ts twoslash
import { AssetBuilder, CredentialListTypes } from '@deltadao/nautilus'
const gated = new AssetBuilder()
// ---cut---
gated
  // Only these addresses may access it.
  .addCredentialAddresses(CredentialListTypes.ALLOW, ['0x0DB823218e337a...'])
  // Or: anyone holding a credential of this type.
  .addRequestCredentials(CredentialListTypes.ALLOW, [ // [!code focus]
    { type: 'VerifiableId', format: 'jwt_vc_json' } // [!code focus]
  ]) // [!code focus]
  .setVcPolicies(CredentialListTypes.ALLOW, ['signature', 'not-before']) // [!code focus]
```

See [Credential-gated assets](/docs/guides/identity) for the whole picture, including the
consumer side.
