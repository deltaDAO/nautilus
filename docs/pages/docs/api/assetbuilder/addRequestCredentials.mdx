# addRequestCredentials

Require verifiable credentials to access the asset.

New in DDO v5, and the core of credential-gated access. Each entry names a credential type and the format it must be presented in.

See the [identity guide](/docs/guides/identity) for the consumer side.

## Usage

```ts twoslash
import { AssetBuilder } from '@deltadao/nautilus'

const assetBuilder = new AssetBuilder()
// ---cut---
import { CredentialListTypes } from '@deltadao/nautilus'

assetBuilder.addRequestCredentials(CredentialListTypes.ALLOW, [ // [!code focus]
  { type: 'VerifiableId', format: 'jwt_vc_json' }, // [!code focus]
  { type: 'UniversityDegree', format: 'jwt_vc_json' } // [!code focus]
]) // [!code focus]
```

Each entry can carry its own `policies`, a policy name or `{ policy, args }`, checked against that credential only. nautilus stores each one JSON-encoded (`'signature'` becomes `'"signature"'`), the form the policy server parses and the enterprise market writes; the policy server skips a per-credential policy that is not valid JSON.

This is where policies with arguments belong. The policy server keeps the arguments of per-credential policies, but drops those of asset- and service-level VC policies, so issuer trust goes here:

```ts
{
  type: 'gx:LegalPerson',
  format: 'jwt_vc_json',
  policies: [
    // Only credentials from these issuers count.
    { policy: 'allowed-issuer', args: ['did:web:delta-dao.com'] }
  ]
}
```

`args` is passed to the walt.id verifier as given: `allowed-issuer` takes one issuer DID or a list of them.

:::warning
walt.id applies these policies by credential type, matched on the last entry of the presented credential's `type` array. A presented credential of another type runs only the asset-level VC policies, so it passes without issuer trust. Bind access to an account with the address allow list; see the [known limitation](/docs/guides/identity#known-limitation-credentials-of-another-type).
:::

## Returns

- Type: [`AssetBuilder`](/docs/api/AssetBuilder)

The asset builder instance, to chain further calls with.
