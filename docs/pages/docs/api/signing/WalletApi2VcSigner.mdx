# WalletApi2VcSigner

Sign the DDO with a key held in walt.id wallet-api2 (`POST /wallet/{walletId}/keys/{keyId}/sign`),
authenticated by an [address sign-in](/docs/api/identity/AddressSignIn) with the `sign-ddo`
scope. The asset's `issuer` is then a DID of the address's wallet, as when the market
publishes.

## Usage

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import {
  Nautilus,
  WalletApi2CredentialProvider,
  WalletApi2VcSigner
} from '@deltadao/nautilus'

const signer = new Wallet('0x...', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
const config = { oceanNodeUri: 'https://node.example.org' }
// ---cut---
const credentials = WalletApi2CredentialProvider.withAddressSignIn({
  gateway: 'https://wallet.example.org/api/address-gateway',
  signer,
  scopes: ['present', 'sign-ddo']
})

const ddoSigner = new WalletApi2VcSigner({ // [!code focus]
  signIn: credentials.signIn, // [!code focus]
  keyId: 'publisher-key', // [!code focus]
  issuer: 'did:web:example.org' // [!code focus]
}) // [!code focus]

const nautilus = await Nautilus.create(signer, { config, credentials, ddoSigner })
```

An organisation admin turns on "Sign asset descriptions (DDOs)" for the address in the wallet
UI. Signing as the organisation's did:web also needs "Present as …".

## Options

| Option | Type | Purpose |
| --- | --- | --- |
| `signIn` | `WalletApi2TokenSource` | `credentials.signIn`, or an `AddressSignIn`, with the scope `sign-ddo`. Required. |
| `keyId` | `string` | The wallet-api2 key to sign with. Required. |
| `issuer` | `string` | The DID the credential is issued as; `keyId`'s key must be one of its verification methods. Required. |
| `walletId` | `string` | Default: the address's wallet. |
| `walletApi` | `string` | Default: the sign-in's gateway. |
| `allowInsecureTransport`, `timeoutMs`, `fetchImpl` | | As for `AddressSignIn`. |

## The document it signs

For address tokens wallet-api2 signs only the market's DDO credential: top-level `@context`,
`id`, `type` (`['VerifiableCredential']`), `issuer`, `version`, `credentialSubject` and
`additionalDdos`, and in `credentialSubject` only `chainId`, `nftAddress`, `metadata`,
`services`, `credentials`, `license`, `dataspace` and `stats`. So, unlike the other signers,
it adds no `iss`, `sub` or `jti`.

`prepareDocument(ddo)` returns the DDO in that shape (it leaves out `credentialSubject.id`,
`credentialSubject.version` and indexer fields). `publish()` and `edit()` call it before they
validate, so the document that is validated, signed and returned in `PublishResponse.ddo` is
one document. `sign()` refuses a DDO with other fields before sending it.

The answer must be a compact JWS of exactly the posted credential, with a `kid` of the
issuer's DID document (`<issuer>#…`) and a header and signature within
`JWS_SIGNING_ALLOWANCE` (1024 characters); the publish flow then checks the payload against
the validated DDO, as for every signer.

## Errors

- `WaltIdWalletError` with `code: 'scope_not_enabled'`: the sign-in has no `sign-ddo` scope
  (refused before anything is sent), or DDO signing is off for the address;
- `code: 'not_a_ddo'`: wallet-api2 refused the body's shape;
- `code: 'did_web_holder_disabled'`: the issuer is the organisation's did:web and "Present
  as …" is off;
- the sign-in codes of [`AddressSignIn`](/docs/api/identity/AddressSignIn#errors).
