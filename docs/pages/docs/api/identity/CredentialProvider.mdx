# CredentialProvider

The interface nautilus calls to answer a verifiable-presentation request. One method.

nautilus opens the policy-server session itself ([`PolicySessionResolver`](/docs/api/identity/PolicySessionResolver)):
it starts the verification, reads the session id and, after the presentation, checks that the
verifier accepted it. A provider does only the step in between: answering the openid4vp
request from a wallet. It is called only for a service whose `SSIpolicy` asks for
credentials; a service gated by addresses only needs no provider.

```ts twoslash
import type { CredentialProvider, CredentialChallenge } from '@deltadao/nautilus'
// ---cut---
class MyProvider implements CredentialProvider {
  async present(challenge: CredentialChallenge): Promise<void> { // [!code focus]
    challenge.asset
    challenge.serviceId
    challenge.consumerAddress
    challenge.node // the node that opened the session and will enforce it
    challenge.sessionId // the session the policy server opened
    challenge.redirectUri // the openid4vp request to answer
  }
}
```

Resolve once the verifier has the presentation. Throw only when you could not present at all
(no matching credential, a rejected request): whether the verifier accepted it is checked by
nautilus afterwards, and a presentation it did not accept is a `PolicyDeniedError`.

:::warning
Ask `challenge.node` for anything about the session, such as the presentation definition, not a
node of your own. A session is only known to the policy server behind the node that opened it:
for a download that is the node in the service's `serviceEndpoint`, which need not be the one
you configured, and for a compute job it is the node running the job.
:::

costs you nothing. See [credential-gated assets](/docs/guides/identity).
