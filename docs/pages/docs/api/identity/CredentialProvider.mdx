# CredentialProvider

The interface nautilus calls to satisfy credential-gated access. One method.

```ts twoslash
import type { CredentialProvider, CredentialChallenge } from '@deltadao/nautilus'
import type { PolicyServerPayload } from '@deltadao/nautilus'
// ---cut---
class MyProvider implements CredentialProvider {
  async resolve(challenge: CredentialChallenge): Promise<PolicyServerPayload | null> { // [!code focus]
    challenge.asset
    challenge.serviceId
    challenge.consumerAddress
    challenge.node // the node that will enforce this policy

    return null // null = nothing to prove
  }
}
```

Returning `null` means the service is not gated, or verification already succeeded — nautilus
then proceeds without a presentation.

:::warning
Resolve against `challenge.node`, not against a node of your own. A verifier session is only
valid on the node that minted it: for a download that is the node in the service's
`serviceEndpoint`, which need not be the one you configured, and for a compute job it is the
node running the job.
:::

## Implementations

| Class | Use |
| --- | --- |
| [`WaltIdCredentialProvider`](/docs/api/identity/WaltIdCredentialProvider) | Drives a real walt.id wallet through the whole exchange. |
| [`StaticCredentialProvider`](/docs/api/identity/StaticCredentialProvider) | You already hold a verifier session id. |
| [`NoopCredentialProvider`](/docs/api/identity/NoopCredentialProvider) | Always `null`. The default. |

:::info
Credentials are always resolved **before** anything is ordered, so a policy you cannot satisfy
costs you nothing. See [credential-gated assets](/docs/guides/identity).
:::
