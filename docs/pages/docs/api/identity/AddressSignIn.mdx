# AddressSignIn

Signs in to walt.id wallet-api2 with the key of an organisation address, through the wallet
UI's address gateway, and hands out the resulting token with a DPoP proof per request. Used by
[`WalletApi2CredentialProvider.withAddressSignIn`](/docs/api/identity/WalletApi2CredentialProvider#withaddresssignin)
and [`WalletApi2VcSigner`](/docs/api/signing/WalletApi2VcSigner). How to set it up:
[Sign in from scripts and CI](/docs/guides/sign-in-scripts).

## Usage

```ts twoslash
import { JsonRpcProvider, Wallet } from 'ethers'
import { AddressSignIn } from '@deltadao/nautilus'

const signer = new Wallet('0x...', new JsonRpcProvider('https://rpc.dev.pontus-x.eu'))
// ---cut---
const signIn = new AddressSignIn({
  gateway: 'https://wallet.example.org/api/address-gateway',
  signer
})

const account = await signIn.check()
console.log(account.address, account.walletId, account.verifiers)
```

Usually you do not create one yourself: `withAddressSignIn` does, and exposes it as
`credentials.signIn`.

## Options

| Option | Type | Purpose |
| --- | --- | --- |
| `gateway` | `string` | The address gateway, exactly as wallet-api2 knows it (`ADDRESS_SIGN_IN_PUBLIC_URL`): `https://<wallet UI>/api/address-gateway`. Required. |
| `signer` | `Signer` | The key of the organisation address. Signs the sign-in message only. Required. |
| `chainId` | `number` | The chain the message names. Default: the signer's provider's network. |
| `smartAccount` | `'auto' \| boolean` | Default `'auto'`. wallet-api2 decides from how the address was linked whether it checks EIP-191 or ERC-1271, so nothing is sent. `true` refuses an address without code (an undeployed account; ERC-6492 is not supported); `'auto'` reads the code only to explain a `sign_in_failed`; `false` reads nothing. |
| `scopes` | `('present' \| 'sign-ddo')[]` | Default `['present']`. Add `'sign-ddo'` to sign DDOs. The scopes are named in the signed message. |
| `allowInsecureTransport` | `boolean` | Accept a plain `http://` gateway on a non-loopback host. Default `false`. |
| `timeoutMs` | `number` | Per request. Default 30 s. |
| `fetchImpl` | `typeof fetch` | For tests. |

## Members

| Member | Purpose |
| --- | --- |
| `getToken()` | A current token: the cached one, or a new sign-in. Renewed 60 s before it expires; concurrent callers share one sign-in. |
| `authorize({ method, url })` | `Authorization: DPoP pxa_…` and a fresh `DPoP` proof for one request. |
| `invalidate(token?)` | Forgets the token (only if it is still the current one). |
| `check()` | Signs in if needed and reads `GET /auth/account`: `{ address, organizationId, walletId, tokenId, expiresAt, scopes, didWebHolder, ddoSigning, verifiers, presentableCredentials }`. |
| `signOut()` | Revokes the token (`POST /auth/logout`) and forgets it. |
| `walletId`, `address` | The address's wallet and the address, once signed in. |
| `gateway`, `endpoint`, `scopes` | The gateway URL and the scopes asked for. |

## What it checks before signing

The challenge's EIP-4361 message must equal, byte for byte, the message nautilus builds from
what it asked for and the nonce and times the server chose:

```text
wallet.example.org wants you to sign in with your Ethereum account:
0x70997970C51812dc3A010C7d01b50e0d17dc79C8

Sign in to the Pontus-X SSI wallet of this address for up to 4 hours, to present credentials to data services. This signature cannot move funds or send transactions.

URI: https://wallet.example.org/api/address-gateway
Version: 1
Chain ID: 32456
Nonce: 9f2c4e6a8b0d1f3e5a7c9e1b3d5f7a9c
Issued At: 2026-11-23T10:00:00Z
Expiration Time: 2026-11-23T10:05:00Z
Resources:
- urn:pontusx:wallet2:scope:present
- urn:ietf:params:oauth:jwk-thumbprint:sha-256:<thumbprint of nautilus's key>
```

The domain and URI are this gateway's, the address is in EIP-55 form, the statement is the one
for the requested scopes (with `sign-ddo`, "and to sign asset descriptions (DDOs) for
publishing"), the resources list the scopes and nautilus's own key, and the window is open now
and at most 5 minutes long. Anything else is refused before the signer sees it
(`message_unexpected`, naming the expected and the actual line).

## DPoP

The key is a P-256 key pair made with WebCrypto for each sign-in, in memory; its private key
cannot be exported and is never logged. Every request carries a proof (RFC 9449): header
`typ: dpop+jwt`, `alg: ES256` and the public `jwk`; claims `htm`, `htu` (the gateway URL and
path, without query), `iat`, a new `jti` and `ath` (the token's SHA-256). wallet-api2 accepts a
proof within ±60 s of its clock.

## Token sources

`WalletApi2HttpClient` and `WalletApi2CredentialProvider` take `token` as a string, a function,
or a `WalletApi2TokenSource`:

```ts
interface WalletApi2TokenSource {
  getToken(): Promise<string>
  invalidate(token?: string): void
  readonly walletId?: string
  readonly address?: string
  /** The only base URL the token may be sent to. */
  readonly endpoint?: string
  /** The headers of one request; default `Authorization: Bearer <getToken()>`. */
  authorize?(request: { method: string; url: string }): Promise<{
    token: string
    headers: Record<string, string>
  }>
}
```

- A string or a function (a Hanko session JWT) is sent as `Authorization: Bearer`, as before.
  `staticTokenSource(token)` wraps one as a source, for tests or your own code.
- An `AddressSignIn` adds `authorize()` (DPoP) and `endpoint` (its gateway: a client for
  another URL refuses it with `wrong_endpoint`).
- After a `401`, a request made with a source object calls `invalidate(token)` and is retried
  once when the source has a new token.

## Errors

From the provider, a [`CredentialPresentationError`](/docs/api/identity/WalletApi2CredentialProvider#errors)
with `reason` and `details.code` (also `details.hint`, `details.status`, `details.retryAfter`);
from `check()`, `getToken()` and `WalletApi2VcSigner`, a `WaltIdWalletError` with `code`,
`hint`, `status` and `retryAfter`. The wallet UI shows the same codes in the address's "Recent
activity".

| Code | Reason | Cause | Who fixes it | Where |
| --- | --- | --- | --- | --- |
| `message_unexpected` | `sign-in` | The sign-in message is not for this gateway, key or request (often `ADDRESS_SIGN_IN_PUBLIC_URL` differs from the URL used). Nothing was signed. | developer, or operator | the `gateway` option; wallet-api2's `ADDRESS_SIGN_IN_PUBLIC_URL` |
| `wrong_endpoint` | `sign-in` | The URL is not the address gateway, or an address token was given to a client for another URL. | developer | the `gateway` / `walletApi` option |
| `not_found` | `sign-in` | The gateway is switched off, or the route does not exist. | operator | `ADDRESS_GATEWAY_ENABLED` in the wallet UI |
| `hanko_token_not_accepted` | `sign-in` | A Hanko token was sent to the gateway. | developer | use `withAddressSignIn`, or the wallet-api2 URL for Hanko tokens |
| `signer_mismatch` | `sign-in` | Signed in as another address than the consumer of the order. | developer | sign with the consumer's key |
| `smart_account_not_deployed` | `sign-in` | `smartAccount: true` and the address has no code. | developer | deploy the account, or sign in with an EOA |
| `chain_not_supported` | `sign-in` | The chain is not enabled for sign-in. | developer, or operator | `chainId`; wallet-api2's `ADDRESS_SIGN_IN_CHAIN_IDS` |
| `challenge_invalid`, `challenge_expired`, `message_mismatch`, `nonce_used` | `sign-in` | The challenge was altered, is older than 5 minutes, or was used twice. | developer | retry; check the system clock |
| `dpop_invalid` | `sign-in` | The DPoP proof was refused (clock off by more than 60 s, another URL). | developer | the system clock; the `gateway` option |
| `sign_in_failed` | `sign-in` | The signature does not prove control of the address (another key, an undeployed or wrongly linked smart account). | developer, or admin | the signer; how the address was linked |
| `address_not_linked` | `sign-in` | The address belongs to no organisation. | admin | Wallet UI → Addresses → Add an address |
| `sign_in_not_allowed_for_organization` | `sign-in` | Sign-in with addresses is not allowed for the organisation. | super admin | Wallet UI → All organizations |
| `sign_in_disabled` | `sign-in` | Sign-in is off for the address (or was turned off). | admin | Wallet UI → Addresses → Sign-in for scripts and servers |
| `too_many_sessions` | `sign-in` | 50 active sessions for the address. | developer, or admin | one sign-in per process, `signOut()`; "End active sessions" |
| `token_invalid`, `token_expired` | `sign-in` | The token was revoked, or expired twice in a row. | developer | normally handled by the retry; check the admin's session list |
| `verifier_not_allowed` | `not-permitted` | The node's verifier is not on the address's verifier list (checked in `prepare()` and by wallet-api2). | admin | the address's verifiers (exact `client_id`, `response_uri` origin) |
| `response_mode_not_allowed` | `not-permitted` | The request would return the presentation to the caller. | node operator | `direct_post` / `direct_post.jwt` requests |
| `did_web_holder_disabled` | `not-permitted` | The holder or DDO issuer is the organisation's did:web and "Present as …" is off. | admin, or developer | the switch; `holderDid` / `issuer` |
| `key_not_allowed`, `holder_changed` | `not-permitted` | Another key or holder than the previewed one. | developer | leave `keyId` and the holder to the preview |
| `consumer_mismatch` | `not-permitted` | The request is bound to another consumer address. | developer | sign in with the address that orders |
| `credential_not_on_access_list` | `not-permitted` | An organisation credential the address may not present. | admin | Wallet UI → Credentials → Addresses (scripts) |
| `route_not_allowed` | `not-permitted` | A route or wallet an address token may not use (also a pinned `walletId` of another wallet). | developer | leave `walletId` out |
| `scope_not_enabled` | `not-permitted` | `sign-ddo` asked for but off, or not asked for at sign-in. | admin, or developer | "Sign asset descriptions (DDOs)"; `scopes` |
| `not_a_ddo` | `not-permitted` | The signed body is not a DDO credential. | developer | sign through the publish flow |
| `handle_evicted` | `wallet-failed` | Newer previews of the token replaced this one; nautilus previews again once. | developer | fewer parallel presentations per sign-in |
| `handle_expired` | `wallet-failed` | The preview is older than 5 minutes or was used. | developer | retry |
| `rate_limited`, `capacity_exhausted` | `wallet-failed` | Too many requests or open previews. | developer | wait `retryAfter` seconds |
| `unavailable`, `invalid_request` | `wallet-failed` | wallet-api2 could not answer, or the request was malformed. | operator, or developer | retry later; report it |

A `no-matching-credential` error with an address token says: "Organisation credentials appear
only if an admin put this address on their access list (Wallet UI → Credentials)."
