# PolicySessionResolver

Opens the policy-server session that ocean-node checks on a download or compute job.
`Nautilus` holds one per instance, built from its `credentials` and `sessionStore`; use it
directly only with the standalone `access(config, context)` / `compute(config, context)`
functions (as `context.policySessions`).

## Usage

```ts twoslash
import {
  PolicySessionResolver,
  WaltIdCredentialProvider
} from '@deltadao/nautilus'
import type { AssetV5, OceanNodeClient } from '@deltadao/nautilus'

declare const node: OceanNodeClient
declare const asset: AssetV5
// ---cut---
const policySessions = new PolicySessionResolver({
  credentials: new WaltIdCredentialProvider(node, { walletApi: 'https://wallet.example.org' })
})

const session = await policySessions.resolve({ // [!code focus]
  node, // the node that checks the policy // [!code focus]
  asset, // [!code focus]
  serviceId: 'a-service-id', // [!code focus]
  consumerAddress: '0x…' // exactly the string the download or compute call uses // [!code focus]
}) // [!code focus]
```

## What `resolve` does

1. Neither the asset nor the service has `credentials` (`{}` counts as having them): `null`.
2. A cached session for (node, asset, service, consumer), opened less than `sessionTtlMs`
   ago: that one. A session that needed a presentation is first checked again
   (`checkSessionId`), since the verifier forgets it when it expires or restarts. An entry
   that is too old, or that the check does not report verified, is deleted and the steps
   below run again.
3. The node has no policy server (`isPSConfigured: false`, or `initializePSVerification`
   answers 404): `null`.
4. The service asks for a verifiable presentation and no credential provider is set: throws,
   before anything is signed.
5. `initiate`: the policy server checks the address and opens a session, or refuses
   (`PolicyDeniedError`). The session id is `message.sessionId`, else the redirect's
   `sessionId=`, `id=` or `state=`.
6. Only when the `SSIpolicy` asks for credentials: the provider's `present()`, then
   `checkSessionId`, which must report `verificationResult: true` (else `PolicyDeniedError`).
7. The session is cached and returned as the payload for the node's `policyServer` slot.

## Options

| Option | Type | Purpose |
| --- | --- | --- |
| `credentials` | `CredentialProvider` | Answers presentation requests. Not needed for address-only gates. |
| `sessionStore` | `SessionStore` | Where verified sessions are kept. Default: [`MemorySessionStore`](/docs/api/identity/MemorySessionStore). |
| `sessionTtlMs` | `number` | How long a cached session is reused, in ms from `initiate`. `0` caches nothing. Default: `DEFAULT_SESSION_TTL_MS`, 2 minutes. |

## Methods

`resolve(request)` · `setCredentialProvider(credentials)` · `clearSessions()`

## Errors

| Error | When |
| --- | --- |
| `PolicyDeniedError` | The policy server refused the consumer (`code`: the HTTP status, `reason`: its message), or the verifier did not accept the presentation (`code` is `undefined`, `reason` names the failed policies). Also carries `did`, `serviceId`, `consumerAddress` and `details`. |
| `OceanNodeError` | The node or the policy server could not answer: a network error, a timeout, a rate limit or a 5xx. |
| `Error` | The service asks for a presentation and no credential provider is set. |

See [credential-gated assets](/docs/guides/identity).
