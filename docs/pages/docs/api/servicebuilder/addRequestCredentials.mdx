# addRequestCredentials

Require verifiable credentials for this service specifically.

The service-level counterpart of [`AssetBuilder.addRequestCredentials`](/docs/api/assetbuilder/addRequestCredentials). The policy server merges both when deciding whether a presentation is needed.

## Usage

```ts twoslash
import {
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const serviceBuilder = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
// ---cut---
import { CredentialListTypes } from '@deltadao/nautilus'

serviceBuilder.addRequestCredentials(CredentialListTypes.ALLOW, [ // [!code focus]
  { type: 'VerifiableId', format: 'jwt_vc_json' } // [!code focus]
]) // [!code focus]
```

Each entry can carry its own `policies`, a policy name or `{ policy, args }`, checked against that credential only. nautilus stores each one JSON-encoded (`'signature'` becomes `'"signature"'`), the form the policy server parses and the enterprise market writes; the policy server skips a per-credential policy that is not valid JSON.

This is where policies with arguments belong. The policy server keeps the arguments of per-credential policies, but drops those of asset- and service-level VC policies, so issuer trust goes here:

```ts
{
  type: 'gx:LegalPerson',
  format: 'jwt_vc_json',
  policies: [
    // Only credentials of this type from these issuers count. A credential of
    // another type skips this check: see the warning below.
    { policy: 'allowed-issuer', args: ['did:web:delta-dao.com'] }
  ]
}
```

`args` is passed to the walt.id verifier as given: `allowed-issuer` takes one issuer DID or a list of them.

:::warning
walt.id applies these policies by credential type, matched on the last entry of the presented credential's `type` array. A presented credential of another type runs only the asset-level VC policies, so it passes without issuer trust: any credential that passes `signature`, self-signed included, satisfies the check. Until the policy server enforces the requested type, the credential check stops only consumers who use a normal wallet: anyone who builds their own presentation passes it with a self-issued credential of another type. The address allow list is the gate that holds, so list the allowed addresses explicitly: an allow list containing `'*'` leaves no gate at all. See the [known limitation](/docs/guides/identity#known-limitation-credentials-of-another-type).
:::

## Returns

- Type: [`ServiceBuilder`](/docs/api/ServiceBuilder)

The service builder instance, to chain further calls with.
