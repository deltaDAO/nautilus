# setRequestCredentials

The service-level counterpart of [`AssetBuilder.setRequestCredentials`](/docs/api/assetbuilder/setRequestCredentials): it replaces this service's request credentials.

Replace the request credentials of a list, keeping its VC and VP policies.

[`addRequestCredentials`](/docs/api/servicebuilder/addRequestCredentials) only adds. On an edit,
use this to remove a requested credential or one of its per-credential policies, e.g. to drop
an attribute requirement.

## Usage

```ts twoslash
import {
  CredentialListTypes,
  FileTypes,
  ServiceBuilder,
  ServiceTypes
} from '@deltadao/nautilus'

const serviceBuilder = new ServiceBuilder<ServiceTypes.ACCESS, FileTypes.URL>({
  serviceType: ServiceTypes.ACCESS
})
// ---cut---
serviceBuilder.setRequestCredentials(CredentialListTypes.ALLOW, [ // [!code focus]
  { // [!code focus]
    type: 'gx:LegalPerson', // [!code focus]
    format: 'jwt_vc_json', // [!code focus]
    policies: [{ policy: 'allowed-issuer', args: ['did:web:delta-dao.com'] }] // [!code focus]
  } // [!code focus]
]) // [!code focus]
```

## Parameters

### list

- Type: `CredentialListTypes`

The list to change, `ALLOW` for gating.

### requestCredentials

- Type: `RequestCredential[]`

The new list, in the form [`addRequestCredentials`](/docs/api/servicebuilder/addRequestCredentials)
takes. Validated the same way: a per-credential `schema` whose `args` are not a JSON Schema
object, an `allowed-issuer` without a list of DIDs, or per-credential policies on
`VerifiableCredential` / `VerifiablePresentation` (which walt.id never runs on a credential
with a more specific type) throw a `TypeError` naming the credential type and the policy.

**An empty list removes the list's `SSIpolicy` entry**, its VC and VP policies included, and
with it the credential gate: the policy server refuses every consumer of an entry that
requests no credential, so keeping it would close the asset. Address and access-list entries
stay. The removal is logged as a `warn` event, `identity.policy.gate_removed` (field `list`).
It throws a `TypeError` instead when that would leave no gate at all: when the service's
remaining allow list admits every address (`'*'`), or, on a service loaded for editing
(`new ServiceBuilder({ asset, serviceId })`), when no address or access-list entry remains
here and the asset's allow list admits every address (empty, or `'*'`). A new service's
builder does not see the asset: with no address entry left, the event says so, and the
asset's list alone decides who gets in, so check that it does not admit everyone.

:::warning[Per-credential policies check only credentials of the requested type]
walt.id runs the `policies` of a request credential (issuer trust, attribute checks) only on
presented credentials whose **last** `type` entry is the requested `type`. A hand-built
presentation holding a self-issued credential of another type skips them, and so does a
self-issued credential that carries the requested type before its last entry, which a normal
wallet presents. They filter honest consumers holding honest credentials; they are not access
control. Keep an explicit address allow list. See the
[known limitation](/docs/guides/identity#known-limitation-credentials-of-another-type).
:::

## Returns

- Type: [`ServiceBuilder`](/docs/api/ServiceBuilder)

The service builder instance, to chain further calls with.
