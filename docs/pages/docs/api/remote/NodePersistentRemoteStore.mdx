# NodePersistentRemoteStore

Store a payload in an ocean-node persistent-storage bucket.

:::danger[Not usable as the DDO store]
ocean-node 4.2 resolves a remote DDO without a consumer address, and a bucket refuses any read
without one, so a DDO stored here would go on chain and never be indexed.
[`publish`](/docs/api/nautilus/publish), [`completePublish`](/docs/api/nautilus/completePublish)
and [`edit`](/docs/api/nautilus/edit) therefore reject this store before any transaction. Use
[`IpfsRemoteStore`](/docs/api/remote/IpfsRemoteStore) or
[`S3RemoteStore`](/docs/api/remote/S3RemoteStore) for the DDO.
:::

The class still works as a plain bucket uploader, for example for files you then reference
with a `nodePersistentStorage` file object.

## Usage

```ts twoslash
import { Nautilus, NodePersistentRemoteStore } from '@deltadao/nautilus'
import { Wallet } from 'ethers'
const nautilus = await Nautilus.create(new Wallet('0x1234'))
// ---cut---
const store = new NodePersistentRemoteStore(nautilus.getNodeClient(), { // [!code focus]
  bucketId: 'my-bucket-id' // [!code focus]
}) // [!code focus]

const fileObject = await store.put('hello', { did: 'notes' })
```

Without `bucketId`, each store instance creates a **new** bucket on first use, and there is no
nautilus call to delete one. Pass `bucketId` to reuse a bucket.

## Parameters

### node

- Type: `OceanNodeClient`

From [`getNodeClient`](/docs/api/nautilus/getNodeClient).

### options

- Type: `NodePersistentRemoteStoreOptions`

| Option | Type | Purpose |
| --- | --- | --- |
| `bucketId` | `string` | Reuse an existing bucket instead of creating one. |
| `accessLists` | — | Restrict who may read the bucket. |
| `label` | `string` | Name the bucket it creates. |
